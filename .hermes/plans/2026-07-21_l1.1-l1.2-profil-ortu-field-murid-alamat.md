## L1.1 — Profil Ortu pisah Ayah & Ibu (tabel `guardians`)
- Q1 = A: kolom FLAT prefix `ayah_*`/`ibu_*` di 1 baris `guardians` (BUKAN tabel `parents` baru).
- Q2 = B: HAPUS kolom lama `nama, no_hp, pekerjaan, tempat_lahir, tanggal_lahir` (redundan
  setelah ada ayah_*/ibu_*). Semua tampilan "Nama Wali"/"No.HP Wali" pakai helper.
- Q2a: default wali = IBU. `namaWali()` = `ibu_nama ?? ayah_nama`. `noHpWali()` = `ibu_no_hp ?? ayah_no_hp`.
- Q3 = Wajib: semua field ortu wajib diisi (per-ortu yang aktif).
- Sentinel "-" DITOLAK → ganti CHECKBOX "Ada" per-ortu:
  * `ada_ayah` / `ada_ibu` (boolean). Default keduanya true.
  * Uncheck → sub-form disable (Alpine) + kolom tak wajib + server simpan NULL semua kolom ortu itu.
  * Guard: minimal salah satu tercentang (tak boleh dua-duanya kosong).
  * Validasi `required_if:ada_ayah,1` / `required_if:ada_ibu,1` per kolom (native, nol magic value).
- Tampilan ortu NULL (opsi A): SEMBUNYIKAN blok ortu yang tak ada (bukan tampil "-").

### Kolom baru `guardians` (per ortu, ×2 ayah/ibu):
nama, tempat_lahir, tanggal_lahir, agama, pendidikan, pekerjaan, pekerjaan_lain, penghasilan, no_hp
+ flag: `ada_ayah`, `ada_ibu`
### Dropdown enum (form):
- Agama: (tidak auto-fill untuk ortu)
- Pendidikan Terakhir: S3/S2/S1/D4/D3/D2/D1/SMA/SMP/SD
- Pekerjaan: PNS/Swasta/Pedagang/TNI/POLRI/Guru/Lainnya (Lainnya → isi `*_pekerjaan_lain`)
- Penghasilan Bulanan: <1jt / 1-2jt / 3-5jt / >5jt
- No.HP: boleh beda ayah vs ibu.
### Form profil wali: 2 sub-form (Ayah + Ibu) dalam 1 card, gaya seperti step pendaftaran.
### `guardians.nama` TETAP ADA — koreksi: user Q2 minta HAPUS nama lama; "nama" wali sekarang
    diturunkan dari `namaWali()`. (Raw brief awal bilang "kolom nama tetap"; keputusan Q2
    final MENGGANTI itu → nama lama dihapus, pakai ayah_nama/ibu_nama.)
