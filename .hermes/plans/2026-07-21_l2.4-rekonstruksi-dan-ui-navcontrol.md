## Bagian 1 — Rekonstruksi `Admin/RegistrationController.php` (prioritas, blockir semua)
Tulis ulang file lengkap dengan `<?php` + namespace `App\Http\Controllers\Admin` + `extends Controller`. Method (sesua kontrak di atas):
1. `index(Request)` — sudah ada (surviving), pertahankan; PERBAIKI variabel L2.4: kirim `$targetTa` (AcademicYear::find(ppdb_ta_target)) + `$tahunBerikutnya` (label next PPDB) agar cocok blade saat ini. (Atau ubah blade — pilih kirim nama variabel yang blade sudah pakai.)
2. `togglePpdb(Request)` — updateOrCreate setting `pendaftaran_dibuka`; audit; redirect back.
3. `storeAcademicYear(Request)` — L2.4 core:
   - Ambil TA target PPDB saat ini (`ppdb_ta_target` → AcademicYear::find, fallback TA aktif).
   - Hitung `tahunBerikutnya = (int)explode('/',$basis)[0]+1 . '/' . +2`.
   - Cari TA tsb di DB (`where('tahun',...)`); bila BELUM ada → `AcademicYear::create(['tahun'=>..., 'is_aktif'=>false])` (TIDAK aktifkan sistem).
   - `Setting::set('ppdb_ta_target', $taBaru->id_academic_years)`.
   - Audit log; redirect back dengan success.
4. `setPpdbTarget(Request)` — validasi `id_academic_year` exists; `Setting::set('ppdb_ta_target', ...)`; redirect back.
5. `daftarUlang(Request)` — `$pending` = PaymentTransaction spp/daftar_ulang pending (eager student); `$tahunOpsi`; filter TA+status+search → `$bills` = ReRegistrationPayment paginate(25) eager student.guardian + academicYear + transactions; `<x-paginate>`.
6. `spp(Request)` — mirip daftarUlang: `$pending`; `$bulanOpsi` (distinct bulan dari MonthlySppBill); `$classes`; filter bulan/TA/kelas/status/search → `$bills` = MonthlySppBill paginate eager; `$statusFilter` (nama beda dari daftarUlang yg pakai `$status`).
7. `show(RegistrationForm $form)` — eager student+guardian+user+documents+payments(user guard); render `admin.registration-detail`.
8. `verifyDocument(Request $r, RegistrationDocument $doc)` — guard: bila `$doc->form->boleh_edit` → redirect back session error 'dokumen'. Validasi status in(diterima,ditolak). Update doc. `advanceToSelectionIfReady()` (mirip P2.3/P3.2): bila form `pembayaran_diverifikasi` & semua dokumen 'diterima' → form `diproses_seleksi` + audit. Bila `$r->wantsJson()` → JSON `{ok,doc_status,form_status,message}`; else redirect back.
9. `verifyPayment(Request $r, PaymentTransaction $tx)` — validasi status; `$r->status==='ditolak'` → service->reject(+catatan) else service->approve; redirect back.
10. `decide(Request $r, RegistrationForm $form)` — guard `status==='diproses_seleksi'` (else session error 'keputusan'); `$r->keputusan` in(lulus,gagal); update form+siswa (lulus→aktif, gagal→nonaktif); BUKA daftar ulang bila lulus (buat ReRegistrationPayment idempoten dari setting nominal_daftar_ulang); audit; Mail::to(user.email) notifikasi; redirect back.
11. `reopenDecision(Request, RegistrationForm $form)` — form→`diproses_seleksi`, siswa→`aktif`; audit; redirect back.
12. `allowEdit(Request, RegistrationForm $form)` — `boleh_edit=true`; redirect back.

Catatan: sesuaikan nama variabel blade (Bagian 1.#1) — blade `registrations.blade` memakai `$targetTa` & `$tahunBerikutnya`; pastikan `index()` mengirim keduanya.

## Bagian 2 — UI L2.4 BARU (A2/B2/C/D2)
