## Goal
Balik default pembayaran: **harus lunas**, cicilan hanya untuk wali ber-izin
(opt-in per-wali, di-set admin). Mekanisme cicil SUDAH ada (PaymentController@store
+ payments.blade `min=1 :max=sisa`) — K10.4 murni soal *gating*, bukan bikin fitur cicil.
Sekalian bikin **Halaman Data Orang Tua** (menjawab "gak punya tab data wali") sebagai
tempat set flag yang benar.

## Konteks kode (sudah ditrace sesi ini)
- Cicil sekarang bebas untuk SEMUA wali. K4.4 cuma buang *teks* "bisa dicicil", bukan mekanismenya.
- Titik penegak "harus lunas" = 1 titik server `Wali\PaymentController@store` (baris ~70 overpay guard)
  + UI `resources/views/wali/payments.blade.php:173` (input nominal). Tak sentuh PaymentVerificationService.
- Relasi sudah lengkap: `Guardian::students()`, `Student::schoolClass`, `SchoolClass::homeroomTeacher`.
  Halaman ortu = view + 1 controller method, reuse pola Data Siswa. Nol relasi baru.
- `guardians` belum punya kolom status/flag. `students.status` = aktif/lulus/nonaktif/dropout.
- Alur akun wali lama sudah ada = **T9.1** (tombol "+ Akun Wali" di Data Siswa, username=password=no_hp,
  must_change_password + ForceChangePassword). Guru pakai pola `is_aktif` + blokir login di AuthController.

## KEPUTUSAN A — TERKUNCI

**A1. Flag `boleh_cicil` di tabel `guardians`** (per-wali). Bukan di students — sekarang ADA
tempat set yang benar (Halaman Data Orang Tua), jadi masalah stale antar-anak hilang: satu tombol per wali.

**A2. Halaman baru Data Orang Tua** — datatable mirip Data Siswa:
- Fitur: search + paginasi 25/hal + filter kelas + filter status.
- Kolom: **Nama Orang Tua · No. HP · Pekerjaan · Nama Anak · Nama Wali Kelas · Kelas · Status · Aksi**.
- Kolom Anak/Wali Kelas/Kelas: bila >1 anak → **ditumpuk vertikal, sejajar per baris anak**
  (anak[i] ↔ wali kelas[i] ↔ kelas[i]). Bila wali kelas & kelas SAMA untuk beberapa anak → tampilkan sekali.
- Aksi: (1) lihat profil ortu lengkap (alamat + list semua anak), (2) edit profil ortu, (3) toggle flag boleh_cicil.

**A3. Filter status ortu = turunan dari anak.** Punya ≥1 anak `status=aktif` → aktif & boleh login.
Tak ada anak aktif → **blokir login** (root-cause 1 titik di `AuthController`, pola sama seperti guru `is_aktif`).
Tidak ada kolom `is_aktif` baru di guardians untuk ini.

**A4. Filter kelas** = tampilkan wali yang punya ≥1 anak di kelas terpilih (baris tetap tampil utuh semua anak).

**A5. Siswa tanpa wali (`id_guardian` NULL)** = TIDAK ada jalur izin cicil di rilis ini. Default harus-lunas.
Bila admin perlu kasih izin → pakai T9.1 (buat akun wali dulu) → wali muncul di Halaman Ortu → set flag.
Ide user "auto-create wali dari NIK→username/NISN→password" **DITOLAK**: NIK/NISN bukan rahasia (identifier
publik) → akun wali lama menganga sebelum wali login; juga menduplikasi T9.1 yang sudah aman (no_hp diverifikasi admin).
